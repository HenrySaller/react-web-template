# Testing Strategy

| What | Tool | Target |
|---|---|---|
| Hooks | Vitest + `renderHook` | 100% meaningful coverage |
| Utils, lib, services | Vitest | 100% meaningful coverage |
| Components | Playwright E2E only | No unit tests |
| User flows | Playwright E2E | All critical paths |

Components are covered exclusively through E2E tests. Do not write unit tests for component files.

# E2E First

New features start with a Playwright test that defines the success criteria. The feature is complete when:
1. The E2E test passes
2. Unit coverage on hooks and services is 100%

```ts
// e2e/checkout.spec.ts — written before implementation begins
import { test, expect } from '@playwright/test'

test.describe('checkout', () => {
  test('user can add item to cart and place an order', async ({ page }) => {
    await page.goto('/products')
    await page.getByRole('button', { name: 'Add to cart' }).first().click()
    await page.goto('/checkout')
    await page.getByRole('button', { name: 'Place order' }).click()
    await expect(page.getByText('Order confirmed')).toBeVisible()
  })
})
```

# Unit Tests — Hooks and Utils

Test behaviour and outcomes — not internal state or implementation details. Assert on what the hook returns and what side effects occur.

```ts
import { renderHook, act } from '@testing-library/react'
import { useCart } from '@/features/cart/hooks/useCart'

it('calculates total after adding items', () => {
  const { result } = renderHook(() => useCart())

  act(() => {
    result.current.addItem({ id: '1', name: 'Widget', price: 10, quantity: 2 })
  })

  expect(result.current.items).toHaveLength(1)
  expect(result.current.total).toBe(20)
})
```

# API Mocking

All tests mock API responses — unit tests and E2E tests alike. Tests never hit real endpoints and never rely on network timing.

- **Unit tests (Vitest)**: Mock `ky` or service functions directly, or use `msw` to intercept at the network layer
- **E2E tests (Playwright)**: Use `page.route()` to intercept and stub API calls

```ts
// E2E: intercept before navigation
test('shows product list', async ({ page }) => {
  await page.route('**/api/products', (route) =>
    route.fulfill({ json: { items: [{ id: '1', name: 'Widget' }] } })
  )
  await page.goto('/products')
  await expect(page.getByText('Widget')).toBeVisible()
})
```

```ts
// Unit: mock the service function
vi.mock('@/features/products/services/getProducts', () => ({
  getProducts: vi.fn().mockResolvedValue([{ id: '1', name: 'Widget' }]),
}))
```

# Coverage Exceptions

Coverage exclusions in `vitest.config.ts` are pattern-based — they apply to categories of files with a documented rationale. Never add individual file paths to the exclusion list.

| Pattern | Rationale |
|---|---|
| `src/routeTree.gen.ts` | Auto-generated by TanStack Router |
| `src/components/ui/**` | Auto-generated by shadcn/ui CLI |
| `src/**/*.stories.tsx` | Storybook stories, not production code |
| `src/main.tsx` | App entry point, covered by E2E |

# Performance

E2E tests capture Web Vitals (LCP, FCP, CLS, TTFB) as part of the test run. Results are signals for iteration — not hard failures. Use the `/perf-report` skill to run the suite and surface metrics.
